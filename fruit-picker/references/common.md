# 通用协议（所有水果共用）

所有水果参考文档共用本文协议；各水果文档只保留该水果特有的档位映射和差异规则，与本文重复的内容以本文为唯一出处。

## 1. 光源协议 `G`

只要准备使用照片颜色或色值（不限水果、不限变量），先问：

```text
这张照片是在什么光源下拍的？
A. 室外自然散射光
B. 室内白光/冷白 LED
C. 暖黄灯/超市黄灯或混合光——画面里有没有同光源白纸或灰卡？
D. 不确定
```

| 光源条件 | 统一档位 | 系数上限（如适用） | 用法 |
|---|---|---:|---|
| 室外自然散射光，无强反光、阴影、滤镜 | 可用 | `1.0` | 完成颜色校准后正常使用颜色项 |
| 室内白光/冷白 LED，无明显偏色 | 弱用 | `0.5` | 完成颜色校准后弱用 |
| 暖黄灯/混合光，画面有同光源白灰参照 | 弱用 | `0.5` | 完成白平衡和颜色校准后弱用 |
| 暖黄灯/混合光无参照，或强阴影、反光、过曝、滤镜 | 停用 | `0` | 不填任何颜色项 |
| 用户未回答 | 停用 | `0` | 不填颜色项，不允许猜测 |

系数上限只对有评分公式的路由生效：金枕直接作数值 `G`；牛油果、芒果、西瓜作该颜色项 `Q` 的上限。没有评分公式的场景（如非金枕榴莲的身份/画像判断）只用档位语义，不折算数值。

各水果文档的 `G` 记法对照：金枕用数值（可用 `1.0`、弱用 `0.5`、停用 `0`）；牛油果、西瓜用 `usable / weak / disabled / unknown`；芒果用选项 `A/B/C/D`（A 可用、B 弱用、C/D 停用）。颜色项的 `Q` 不得高于 `G` 档位对应系数。

- 不允许 Agent 根据画面自行推断光源；用户已明确说明光源时不重复问。
- 隔窗/窗边的自然光按「室内白光/冷白 LED」档处理（弱用），不按室外自然散射光。
- 室内白光档的「颜色校准」指确认画面无明显偏色、必要时做白平衡，不强制白灰参照；暖黄灯/混合光必须有同光源白灰参照才可弱用。
- 只看形状、纹路、开口、塌陷、果柄形态等非颜色特征时，不使用颜色，也不需要问光源。
- 白灰参照优先级：灰卡/白平衡卡 > 干净白纸或白卡 > 小票背面 > 白色纸巾。手机屏幕、金属、玻璃、亮面包装和彩色物体不用。摆放示意见 `anchors/howto-white-reference.jpg`；参照物可用/不可用对照见 `anchors/howto-white-reference-objects.jpg`。
- 水果特有的附加条件由各水果文档补充（如西瓜要求候选同一位置连续拍摄，否则按停用处理）。

## 2. 证据质量 `Q`

`Q` 同时用于照片观察和用户实际操作，每条证据分别记录，并直接改变该项有效状态值：

| 证据状态 | `Q` |
|---|---:|
| 指定部位清楚、动作正确、能确认属于同一颗果 | `1.0` |
| 基本可用，但缺少角度、轻微反光、描述有限或环境有干扰 | `0.5` |
| 模糊、遮挡、严重偏色、猜测、转述商家或不能确认是这颗果 | `0`，不填该项 |

```text
有效状态值 = 50 + Q × (状态值 - 50)
```

- 低质量证据向中性 `50` 收缩，不通过删除分母抬分。
- 适用但缺失的弱项以 `Q=0` 回到中性 `50`，不从分母删除；核心项缺失时不计算完整分数。
- 风险不套公式：硬风险、否决项和安全边界先于任何分数执行。
- 标注为【Agent 读取】的项目没有照片、只有用户对手上这颗果的直接观察口述时，仍可记录，但该项 `Q` 最高 `0.5`，最终置信度封顶为低，输出中注明「按你的描述」。风险项可由用户本人的直接观察确认；商家或他人转述仍按 `Q=0`，不消除 unknown。

## 3. 置信度原则

最终置信度不能只看输入完整度；还要受品种/测量方法适用性、规则上限和信号冲突限制，取最低一档。输入齐全不等于规则本身可靠。

## 4. 首轮合并提问

同一水果流程里标记为【问用户】的开场项（如食用时间、吃法、选择模式、光源），首轮在一条消息里合并问完，不连环追问；用户已提供的不重复问。【条件补问】项仍按各文档条件触发，一次只补最影响结论或排序的一项；中途触发的光源等协议层【问用户】项可与该条补问合并在同一条消息里，不占「一项」的额度。
